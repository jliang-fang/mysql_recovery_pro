## 一、设计目标

### 1.1 核心目标

1. **全版本兼容**: 支持 MySQL 5.6/5.7/8.0/8.4/9.0 的页结构差异
2. **自动探测**: 通过 Page 0/3 的特征码自动判定版本及行格式
3. **深度解析**: 完整解析 B+树索引页、Undo Log 页、SDI 页等
4. **高性能**: 支持 io_uring 裸盘级别的扫描效率
5. **企业级特性**: TDE 解密、Instant DDL、高可用

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **策略模式** | 不同 MySQL 版本使用不同的解析策略 |
| **工厂模式** | 自动创建对应版本的解析器 |
| **模板方法** | 统一接口，差异化实现 |
| **零拷贝读取** | 使用 mmap/io_uring 提升性能 |
| **防御性编程** | 严格校验页结构，容忍部分损坏 |

## 二、MySQL 版本差异分析

### 2.1 系统字典差异

| 特征 | MySQL 5.6/5.7 | MySQL 8.0+ |
|------|---------------|------------|
| 系统字典位置 | ibdata1 (共享) | mysql.ibd (独立) |
| 元数据格式 | 系统表 | SDI (Serialized Dictionary Info) |
| SDI 支持 | ❌ 不支持 | ✅ 支持 |
| 字典表空间 | system tablespace | data dictionary tablespace |

### 2.2 行格式差异

| 行格式 | MySQL 版本 | 记录头大小 | 字段偏移计算 | BLOB 存储 |
|--------|------------|------------|-------------|-----------|
| REDUNDANT | 4.1-5.0 | 6 bytes | 从末尾反向计算 | inline |
| COMPACT | 5.0+ | 5 bytes | 从末尾反向计算 | inline |
| DYNAMIC | 5.7+ | 5 bytes | 动态计算 | overflow page |
| COMPRESSED | 5.7+ | 5 bytes | 动态计算 | compressed |

### 2.3 页头字段差异

| 字段 | MySQL 5.6/5.7 | MySQL 8.0+ | 说明 |
|------|---------------|------------|------|
| PAGE_N_DIRECT_PAGES | ❌ 不存在 | ✅ 存在 | 8.0+ 新增 |
| Instant DDL Metadata | ❌ 不存在 | ✅ 存在 | 8.0+ 新增 |
| PAGE_MAX_TRX_ID | 页头 (42-47) | 页头/Infimum | 8.0+ 移至 Infimum |
| SDI | ❌ 不存在 | ✅ 存在 | 8.0+ 元数据 |

### 2.4 页类型差异

| 页类型 | 值 | MySQL 5.6/5.7 | MySQL 8.0+ | 说明 |
|--------|-----|---------------|------------|------|
| FIL_PAGE_INDEX | 9969 (0x26f1) | ✅ | ✅ | B+Tree 索引页 |
| FIL_PAGE_SDI | 9971 (0x26f3) | ❌ | ✅ | SDI 元数据页 |
| FIL_PAGE_UNDO_LOG | 9970 (0x26f2) | ✅ | ✅ | Undo Log 页 |
| FIL_PAGE_TYPE_BLOB | 9972 (0x26f4) | ❌ | ✅ | BLOB 页 |
| FIL_PAGE_COMPRESSED | 9973 (0x26f5) | ❌ | ✅ | 压缩页 |

### 3.3 版本特定解析器

#### 3.3.1 GenericPageParser (通用实现)

- 提供基础的页解析功能
- 子类可覆盖特定方法
- 实现通用的行格式解析逻辑

#### 3.3.2 MySQL56PageParser (MySQL 5.6/5.7)

**支持特性**:
- REDUNDANT 行格式
- COMPACT 行格式
- ibdata1 系统字典
- 无 SDI（元数据存储在系统表中）

**关键差异**:
- PAGE_MAX_TRX_ID 位于页头 (42-47)
- 无 PAGE_N_DIRECT_PAGES 字段
- 无 Instant DDL 元数据

#### 3.3.3 MySQL80PageParser (MySQL 8.0)

**支持特性**:
- REDUNDANT/COMPACT/DYNAMIC/COMPRESSED 行格式
- 独立的 mysql.ibd 系统字典
- SDI (Serialized Dictionary Info)
- Instant DDL

**关键差异**:
- PAGE_MAX_TRX_ID 可能位于 Infimum 记录
- 有 PAGE_N_DIRECT_PAGES 字段
- 有 Instant DDL 元数据 (offset 54-57)

#### 3.3.4 MySQL84PageParser (MySQL 8.4+)

**支持特性**:
- 所有 MySQL 8.0 行格式
- 增强的 SDI 支持
- 更好的压缩支持

**关键差异**:
- SDI JSON 格式增强
- 新的页类型支持

#### 3.3.5 MySQL90PageParser (MySQL 9.0)

**支持特性**:
- 所有 MySQL 8.x 行格式
- 预留新特性支持

**关键差异**:
- 预留字段用于未来扩展

## 四、页结构详解

### 4.1 FIL Header (0-37 bytes)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0-3 | 4 bytes | FIL_PAGE_PREV | 前一个页号 (索引页) |
| 4-7 | 4 bytes | FIL_PAGE_NEXT | 后一个页号 (索引页) |
| 8-15 | 8 bytes | FIL_PAGE_LSN | 日志序列号 |
| 16-17 | 2 bytes | FIL_PAGE_TYPE | 页类型 |
| 18-21 | 4 bytes | FIL_PAGE_SPACE_ID | 空间ID |
| 22-23 | 2 bytes | FIL_PAGE_PAGE_NO | 页号 |
| 24-27 | 4 bytes | FIL_PAGE_DATA_END | 数据结束标记 |
| 28-31 | 4 bytes | FIL_PAGE_CHECKSUM | 校验和 |

### 4.2 Page Header (38+ bytes)

| 偏移 | 大小 | 字段 | MySQL 5.6/5.7 | MySQL 8.0+ |
|------|------|------|---------------|------------|
| 0-1 | 2 bytes | PAGE_N_DIR_SLOTS | ✅ | ✅ |
| 2-3 | 2 bytes | PAGE_HEAP_TOP | ✅ | ✅ |
| 4-5 | 2 bytes | PAGE_N_HEAP | ✅ | ✅ |
| 6-7 | 2 bytes | PAGE_FREE | ✅ | ✅ |
| 8-9 | 2 bytes | PAGE_GARBAGE_END | ✅ | ✅ |
| 10-11 | 2 bytes | PAGE_LAST_INSERT | ✅ | ✅ |
| 12-13 | 2 bytes | PAGE_DIRECTION | ✅ | ✅ |
| 14-15 | 2 bytes | PAGE_N_DIRECT_PAGES | ❌ | ✅ |
| 16-17 | 2 bytes | PAGE_N_RECS | ✅ | ✅ |
| 18-23 | 6 bytes | PAGE_MAX_TRX_ID | ✅ (页头) | ✅ (页头/Infimum) |
| 24-25 | 2 bytes | PAGE_CHECKSUM_START | ✅ | ✅ |
| 26-29 | 4 bytes | PAGE_CHECKSUM | ✅ | ✅ |
| 30-31 | 2 bytes | INSTANT_METADATA_OFFSET | ❌ | ✅ |
| 32-33 | 2 bytes | INSTANT_METADATA_VERSION | ❌ | ✅ |

### 4.3 记录头结构

#### REDUNDANT 格式 (6字节)

```
Byte 0:   n_owned (4 bits) + status (2 bits) + flag (1 bit) + next_rec_high (1 bit)
Bytes 1-2: next_record_offset (14 bits)
Bytes 3-4: heap_no (14 bits)
Bytes 5-6: record_length (14 bits)
```

#### COMPACT 格式 (5字节)

```
Byte 0:   info_bits (8 bits)
Bytes 1-2: next_record_offset (14 bits)
Bytes 3-4: heap_no (14 bits)
Byte 5:   n_fields (8 bits)
```

#### DYNAMIC 格式 (5字节 + Instant DDL)

```
同 COMPACT 格式，外加:
Byte 6:   metadata_version
Byte 7:   instant_flags
```

### 4.4 行格式识别

#### 从 BTR Header Flags 识别

```cpp
// Flags 位于偏移 38 + 42 = 80
uint16_t flags = read_le<uint16_t>(data, 80);
uint8_t row_format_val = flags & 0x07;

switch (row_format_val) {
    case 0: return RowFormat::REDUNDANT;
    case 1: return RowFormat::COMPACT;
    case 2: return RowFormat::DYNAMIC;
    case 3: return RowFormat::COMPRESSED;
}
```

#### 从 Record Header 识别

```cpp
// 检查 extra_bytes (第5字节)
if (record_header[4] == 6) {
    return RowFormat::REDUNDANT;
}

// COMPACT/DYNAMIC: extra_bytes = 5
return RowFormat::COMPACT;
```

MySQLVersion PageParserFactory::detect_mysql_version(const uint8_t* data, size_t size) {
    // 1. 首先尝试从 SDI 页识别版本

### 5.2 行格式探测

```cpp
RowFormat PageParserFactory::detect_row_format(const uint8_t* data, size_t size) {
    // 从 BTR header 的 flags 中提取行格式
    if (size < FIL_HEADER_SIZE + 44) {
        return RowFormat::UNKNOWN;
    }

    uint16_t flags = read_le<uint16_t>(data, FIL_HEADER_SIZE + 42);
    uint8_t row_format_val = flags & 0x07;

    switch (row_format_val) {
        case 0: return RowFormat::REDUNDANT;
        case 1: return RowFormat::COMPACT;
        case 2: return RowFormat::DYNAMIC;
        case 3: return RowFormat::COMPRESSED;
        default: return RowFormat::UNKNOWN;
    }
}
```

## 九、扩展性设计

### 9.1 添加新版本支持

要添加对新 MySQL 版本的支持，只需：

1. 创建新的解析器类（继承 `GenericPageParser`）
2. 实现 `parse_header()` 和 `parse_records()` 方法
3. 在 `PageParserFactory::create_parser()` 中添加版本判断

```cpp
class MySQL91PageParser : public MySQL90PageParser {
public:
    explicit MySQL91PageParser(RowFormat format);
    bool parse_header(const uint8_t* data, size_t size) override;
    // ... 其他方法
};

// 在 PageParserFactory::create_parser() 中添加
case MySQLVersion::MYSQL_91:
    return std::make_unique<MySQL91PageParser>(format);
```

### 9.2 添加新行格式

要添加对新行格式的支持，只需：

1. 在 `RowFormat` 枚举中添加新值
2. 更新 `PageParserFactory::detect_row_format()` 方法
3. 在相应的解析器中实现新格式的解析逻辑

    // 按页号排序
    std::sort(pages_.begin(), pages_.end(),
        [](const auto& a, const auto& b) { return a.first < b.first; });

    // 检查页链连续性
    for (size_t i = 0; i < pages_.size() - 1; ++i) {
        uint32_t current_page = pages_[i].first;
        uint32_t next_page = pages_[i + 1].first;

        // 检查是否连续
        if (next_page != current_page + 1) {
            stats_.broken_chain++;
        }
    }

    // 检查循环引用
    std::set<uint32_t> seen;
    for (const auto& [page_no, data] : pages_) {
        if (seen.find(page_no) != seen.end()) {
            stats_.circular_reference++;
            break;
        }
        seen.insert(page_no);
    }

    return stats_.broken_chain == 0 && stats_.circular_reference == 0;
}

bool BlobPageChain::is_valid(const std::function<std::optional<std::vector<uint8_t>>(uint32_t, uint32_t)>& page_reader,
                             bool strict_mode) const {
    // 验证页链连续性
    for (size_t i = 0; i < pages.size(); ++i) {
        auto [space_id, page_no] = pages[i];
        auto page_data_opt = page_reader(space_id, page_no);

        if (!page_data_opt || page_data_opt->size() < BTR_BPAGE_LEN + 4) {
            if (strict_mode) {
                return false;
            }
        }

        // 验证下一个页号（除最后一页外）
        if (i < pages.size() - 1) {
            uint32_t next_expected = pages[i + 1].second;
            uint32_t actual_next = read_le<uint32_t>(page_data_opt->data(), BTR_BPAGE_NEXT);

            if (actual_next != next_expected) {
                if (strict_mode) {
                    return false;
                }
            }
        }
    }

    return true;
}
